# 调研文档与实验记录索引

- 维护日期：2026-10-04
- 目录定位：当前代码库的研究、验证和设计草稿区
- 适用范围：本目录中的所有调研报告、实验记录、技术判断和阶段性设计材料

## 目录原则

本目录不是随手堆放结论或标签的临时目录。我们做过的每一项重要实验，都必须在这里留下**有条理、可复核、能解释结论边界**的文档记录。

必须遵守以下原则：

1. **实验必须留痕。** 只要执行过构建、测试、部署、数据库操作、性能探针、兼容性验证、故障复现或外部资料核查，就要记录目的、过程、结果和结论。
2. **记录必须系统化。** 不使用“已测试”“可行”“失败”这类孤立标签替代实验记录；结论必须能追溯到命令、配置、代码版本和观测结果。
3. **事实、推断和建议必须分开。** 明确哪些是直接观察到的事实，哪些是基于证据的推断，哪些是未来方案或待验证假设。
4. **负面结果同样重要。** 失败、跳过、环境不满足、性能不达标和未能验证的部分都必须记录，不得只保留成功结果。
5. **优先落在 `docs/drafts/`。** 研究阶段尽量不修改生产代码；如果实验确实需要代码变更，必须在记录中说明变更文件、理由、影响和回滚方式。
6. **敏感信息必须脱敏。** 数据库密码、访问令牌、个人凭据和内部地址不得写入文档；命令可以保留结构，但凭据使用 `<redacted>` 或环境变量占位符。

2. 阅读 `remote-durable-workspace-research.md`，掌握问题背景、架构判断和待解决风险。

## 实验记录最低结构

每一份独立实验记录至少应包含以下章节。实验很小也不能省略关键证据；可以写“不适用”，但不要悄悄跳过。

### 1. 实验元数据

- 实验名称和唯一日期；
- 实验目的；
- 执行人或执行主体；
- 仓库分支、commit、未提交变更情况；
- 记录状态：`进行中`、`成功`、`部分成功`、`失败`、`阻塞`或`已废弃`。

### 2. 问题与假设

说明要验证的具体问题，以及实验前的假设。例如：

> 假设：macOS 不需要 Linux FUSE，只要使用 TigerFS 的 NFS 适配路径即可完成基本工作区操作。

不要把实验结论倒写成实验目的。

### 3. 环境与前置条件

记录所有影响结果的条件：

- 操作系统、CPU 架构和工具链版本；
- 数据库版本、扩展、license/edition mode 和连接方式；
- Docker/OrbStack 容器、镜像、端口和平台；
- 代理、镜像源、环境变量和权限要求；
- 测试数据、数据库 schema、临时目录和挂载方式。

### 4. 执行过程

保留可复现的命令和关键配置，并说明执行顺序。命令中的密码和令牌必须脱敏，但不能删掉足以判断实验如何运行的结构信息。

### 5. 观测结果

记录实际观察到的内容，而不是只写主观判断：

- 命令退出码；
- 通过、失败、跳过和错误信息；
- 耗时、吞吐、数量或其他指标；
- 关键日志摘要；
- 与预期不一致的行为。

### 6. 结论与证据等级

结论应明确标注性质：

- **已验证事实**：由本地命令、代码、测试或官方资料直接支持；
- **有条件结论**：在明确环境和前置条件下成立；
- **推断**：根据事实推导出的设计判断；
- **待验证假设**：尚无足够实验或资料支持。

避免使用没有范围限定的“支持”“兼容”“可行”“不依赖”等绝对表述。

### 7. 限制、失败与替代解释

说明实验没有覆盖的范围、失败原因是否已确认、是否存在环境因素、是否可能有其他解释，以及哪些结论不能从本实验推出。

### 8. 复现与清理

记录复现实验所需的最短步骤，以及实验结束后的资源状态：

- 临时容器、数据库、镜像、挂载点和测试目录是否删除；
- 保留了哪些资源及其用途；
- 是否修改了本机服务或仓库配置；
- 如何恢复实验前状态。

### 9. 对项目的影响

说明实验是否改变了：

- 架构判断；
- 产品或平台支持边界；
- 后续实现计划；
- 风险清单；
- 需要新增的测试或文档。

## 文档维护规则

- 新增调研或实验文档后，必须在“现有成果”或相应主题索引中登记。
- 新实验优先追加到已有主题记录；只有当实验具有独立复现价值或篇幅明显增长时，才新建文件。
- 报告引用实验时，必须链接到具体记录文件，并尽量指出章节或命令位置。
- 同一结论发生变化时，不删除历史结论；应追加复测日期、环境差异和修正原因。
- 文档完成后执行 `git diff --check`，并检查是否泄露凭据、是否混淆事实与推断、是否记录了清理结果。
- 研究阶段的文档变更统一集中在 `docs/drafts/`；需要升级为正式项目文档时，另行评审和迁移。
